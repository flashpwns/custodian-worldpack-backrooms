# Player navigation

YB-30 Pass 1 organizes the desktop application as World Library, Create World, Active World, Settings, and explicitly optional developer tools. The library uses player metadata only: a world name, last-played context, and legitimate save actions. It never shows world/session IDs, source provenance, claims, or simulation state.

Creation asks for a name, an initial experience, optional repeatable seed, and Guided Introductions. The latter is presentation preference, never canonical history. Mode entry explains broad play style without spoilers: Clear-Q4 is operational field work; Beck is institutional work; Nullzone is personal evidence; Lost is minimal exploration.

Active play preserves the current session while navigation changes only renderer state. Mode-specific surfaces retain their existing safe projections; contextual detail remains secondary. Lost has no institutional navigation or quest log. Offline presentation remains playable through deterministic fallbacks and structured controls. Pass 2 added reactive in-universe visual framing; Pass 3 adds application-only request feedback and discards responses that no longer belong to the active world or experience.

Pass 4 adds a contextual “What do I know?” record after the primary input. It
organizes only the active observer’s known material and remains mode-specific.
The library stays recent-first, supports name filtering and metadata-only
renaming, and explains export. Resume reuses an existing compatible session
without silently advancing the world.

Pass 5 makes the same navigation keyboard-operable with visible focus and
bounded text scaling. Appearance, motion, and Guided Introductions are global
player preferences; they never alter canonical world identity or progress.
