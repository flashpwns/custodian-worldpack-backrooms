# Emergent story threads

Story threads are derived, noncanonical analysis of existing `yellow-beast-world-history@v1` events. Runs create history first; `tools/story-threads.js` then recognizes structured anchors such as a persistent artifact, phenomenon identity, character identity, region mutation, or explicitly conflicting report subject. It never calls a world-history mutation API and stores no thread cache in a world export.

Current categories are recovered object, repeated phenomenon, personnel disappearance, contradictory reports, and unexplained environment change. They use candidate and active presentation states derived from event count; they do not prescribe escalation, resolution, or a future event. Similar events never become a common cause merely by resemblance.

The shared derived index may recognize a common canonical anchor, while `observerView` filters its supporting events by profile. Q4 receives operational follow-up, Beck receives report/personnel matters, Nullzone receives personal observations, and Lost receives implicit continuity rather than an explicit case list. Thread IDs, canonical anchors, and source metadata remain debug/report material.

Player hypotheses and future authored scenarios remain distinct from this module. A thread cannot move an object, deliver a report, revive a character, spawn an anomaly, or change simulation probabilities. Provider summary input is observer-safe; unsupported causes, culprits, motives, and future events are rejected in favor of a deterministic fallback.

`npm run story-thread-report` reports derivation properties, category counts, cross-mode filtering, persistence/rebuild behavior, and safety invariants.
