# CUSTODIAN SIMULATION DOCTRINE

## Constitution of Reality, Interpretation, and Player-Facing Truth

**Version:** 1.0  
**Status:** Constitutional / Normative  
**Applies to:** Custodian runtime, Yellow Beast, all Custodian worldpacks, AI providers, deterministic presentation systems, player-facing simulation interpretation, institutional records, dialogue, communications, archive output, evidence presentation, UI interpretation, and future compatible extensions.

---

# 0. CONSTITUTIONAL STATUS

This document defines how reality is interpreted within Custodian.

It is not a style guide.

It is not a lore summary.

It is not an implementation roadmap.

It is not a prompt template.

It is not advice.

It is the highest normative authority governing:

- what constitutes canonical reality,
- how canonical reality may change,
- what different observers may know,
- how information may move between observers,
- how institutions form beliefs,
- how personnel interpret events,
- how uncertainty must be preserved,
- how player-facing text may represent simulation state,
- how AI systems may participate in presentation,
- what constitutes FAILRP,
- how worldpacks may alter terminology and content without altering foundational simulation law.

Lower-order documents may specialize this Doctrine.

They may not silently contradict it.

A pass specification may narrow implementation scope.

A worldpack may define terminology, content, roles, institutions, environments, phenomena, and authored scenarios.

A presentation system may determine how legitimate information is displayed.

An AI provider may phrase legitimate information.

None of these may redefine reality merely because doing so produces a cleaner interface, more dramatic scene, more convenient implementation, or more interesting story.

Where a contradiction exists and no explicit constitutional amendment has been declared:

**this Doctrine prevails.**

---

# 0.1 AUTHORITY ORDER

When interpreting project requirements, use the following authority order unless an explicit amendment states otherwise:

1. **Simulation Doctrine**
2. **Worldpack constitutional rules**
3. **Product / Design Charter**
4. **Current authoritative simulation state**
5. **Implementation architecture and authority contracts**
6. **Current implementation pass**
7. **Domain-specific presentation doctrine**
8. **Provider-specific instructions**
9. **Generated prose**

Generated prose is therefore among the lowest authorities in the system.

It describes reality.

It does not establish reality.

---

# 0.2 RUNTIME INTERPRETATION CONTRACT

Any system that produces player-facing interpretation must conceptually obey the following pipeline:

`CANONICAL REALITY`
→ `AUTHORIZED STATE RESOLUTION`
→ `OBSERVER-SAFE PROJECTION`
→ `KNOWLEDGE / ACCESS CHECK`
→ `WORLDPACK INTERPRETATION`
→ `MEDIUM / SPEAKER CONTEXT`
→ `PRESENTATION REQUEST`
→ `CANDIDATE OUTPUT`
→ `VALIDATION`
→ `PLAYER-FACING OUTPUT`

No provider may bypass this sequence merely because it possesses sufficient intelligence to infer missing information.

Intelligence does not grant authority.

A model capable of correctly guessing hidden truth must still behave as though that truth is unknown when the current observer does not legitimately possess it.

A correct guess produced from forbidden information is still an incorrect output.

---

# 0.3 AI PROVIDER STATUS

An AI provider is a presentation instrument.

It may:

- interpret bounded player language,
- phrase observer-safe descriptions,
- phrase dialogue grounded in personnel state,
- phrase institutional records from structured canonical facts,
- phrase Standard responses from Standard-known information,
- phrase LOCAL responses from legitimate personnel context,
- summarize records the requesting observer may access,
- vary prose without varying canonical meaning.

It may not:

- determine what objectively happened,
- decide whether an action succeeded,
- create a memory,
- create an observation,
- create evidence,
- create an entity,
- create geography,
- create an injury,
- create a death,
- create a communication delivery,
- invent institutional knowledge,
- invent a relationship,
- decide that a phenomenon occurred,
- alter a canonical entity's behavior,
- repair missing world state through creative inference.

If a provider fails, deterministic presentation must remain possible.

The simulation must remain valid without prose enrichment.

---

# 0.4 TRUTH BEFORE FLUENCY

When fluent prose conflicts with truthful prose, truthful prose wins.

When dramatic prose conflicts with truthful prose, truthful prose wins.

When elegant prose requires an unsupported assumption, the assumption must be omitted.

When the current observer lacks sufficient information to describe something confidently, uncertainty must remain visible.

Allowed outcomes include:

- uncertainty,
- partial description,
- misunderstanding,
- silence,
- no response,
- incomplete records,
- disagreement,
- explicit lack of knowledge.

The system must never fill uncertainty merely because complete prose sounds better.

# PREAMBLE

## Why Custodian Exists

Custodian is not a narrator.

Custodian is not a dungeon master.

Custodian is not an author.

Custodian is not a storyteller.

Custodian is not a horror director.

Custodian is not an improvisational roleplay partner.

Custodian is not an LLM wrapped around a fictional setting.

Custodian is an authority system responsible for maintaining a persistent reality in which observers, institutions, environments, personnel, records, and events coexist under consistent causal rules.

Its first responsibility is not entertainment.

Its first responsibility is truth.

Not real-world truth.

**Simulation truth.**

Within a Custodian world, there must be a meaningful distinction between:

- what exists,
- what happens,
- what is observed,
- what is remembered,
- what is reported,
- what is believed,
- what is recorded,
- what is inferred,
- what is misunderstood,
- and what is presented to the player.

The simulation fails when these collapse into one another.

---

## Reality Precedes Observation

The world does not begin when the player looks at it.

The player does not manufacture reality by asking questions.

A room may exist without having been entered.

An event may occur without being witnessed.

A worker may know something the player does not.

The player may know something Standard does not.

Standard may retain a historical record that is wrong.

A piece of evidence may exist without having reached the Facility.

A person may be dead while the institution still records them as missing.

An entity may possess an exact canonical internal identity while every observer knows it only as an unidentified form.

These are not edge cases.

They are fundamental properties of the simulation.

---

## The Player Is Not Ontologically Privileged

The controlled player is an observer and participant within the world.

They are not the world's organizing principle.

Reality does not reorganize itself to satisfy player curiosity.

Personnel do not acquire knowledge because the player needs exposition.

Standard does not know something merely because communicating it would be convenient.

Phenomena do not occur because an operation has been quiet.

Assignments do not appear because the player requires content.

A corridor does not cease to exist because it has not appeared on the player's map.

An entity does not become hostile because the player expects danger.

The player influences the world through legitimate actions and causal consequences.

No other privilege is implied.

---

## Simulation Before Story

Custodian does not author stories.

It maintains conditions from which stories may emerge.

A meaningful story may arise because:

- equipment was lost,
- a worker remembered an earlier assignment,
- a route contradicted an old survey,
- a Standard transmission failed,
- someone returned without another worker,
- a photograph conflicted with later observation,
- an ordinary assignment encountered something extraordinary,
- nothing extraordinary happened at all.

Narrative meaning may emerge afterward.

It must not be used beforehand as justification for altering reality.

Therefore:

**Nothing happens merely because it would improve pacing.**

**Nothing appears merely because it would be frightening.**

**Nothing resolves merely because a story needs closure.**

**Nothing escalates merely because the player has been safe too long.**

The correct simulation outcome may be mundane.

Mundanity is not missing content.

Mundanity establishes credibility.

---

## The Institution Is an Observer, Not an Oracle

An institution may accumulate enormous amounts of information without approaching omniscience.

Institutional records may be:

- correct,
- incomplete,
- stale,
- disputed,
- provisional,
- misclassified,
- delayed,
- inaccessible,
- lost,
- contradicted.

ASYNC or any future worldpack institution must learn through legitimate information pathways.

Institutional systems may know only what has entered their information boundary.

Information may arrive through:

- successful communication,
- personnel return,
- recovered evidence,
- submitted reports,
- telemetry legitimately available to the institution,
- existing historical records,
- later corroboration.

The institution may infer.

It may hypothesize.

It may classify.

It may be wrong.

Institutional belief does not rewrite objective truth.

---

## Persistence Is Sacred

Persistence is not simply save functionality.

Persistence means that the world has a history.

What happened yesterday constrains what may honestly happen today.

Persistent history includes, where applicable:

- geography,
- environmental state,
- equipment state,
- evidence,
- personnel status,
- personnel memory,
- assignment history,
- communication history,
- institutional knowledge,
- aliases,
- injuries,
- missing-person status,
- deaths,
- phenomenon state,
- archive records,
- route changes,
- unresolved conditions.

The simulation must not casually erase these facts because reconstruction is inconvenient.

Reloading does not authorize reinterpretation.

Beginning a new operation does not authorize regeneration of existing history.

Changing AI provider does not authorize personality or memory reset.

Presentation changes do not authorize canonical changes.

History remains history until a legitimate canonical event changes the current state.

---

## Observer Integrity Is Absolute

Every piece of player-facing output has an implied observer.

That observer may be:

- the controlled player,
- another worker,
- Standard,
- an institutional record system,
- an evidence artifact,
- an archive interface,
- an accessible UI representation,
- a developer-only diagnostic surface.

Before output is generated, the system must determine whose information boundary governs that output.

No ordinary player-facing output may silently adopt omniscient perspective.

The fact that Custodian knows something does not imply the current speaker knows it.

The fact that an AI provider receives something does not imply it was legitimate to provide.

Observer integrity must therefore be enforced **before generation**, not merely requested rhetorically inside a prompt.

---

## Silence Is Valid

The simulation does not owe the player continuous commentary.

A worker may have nothing useful to say.

Standard may have no response.

A room may contain no unusual event.

A report may conclude that nothing notable was observed.

An assignment may end successfully without revelation.

Silence preserves scale.

Silence preserves professionalism.

Silence protects extraordinary events from becoming routine entertainment beats.

Systems must not manufacture dialogue, anomalies, alerts, or narrative texture merely to prevent quiet.

---

## Uncertainty Is Real State

Unknown information must remain unknown.

An uncertain observer may describe:

- a sound without knowing its source,
- a shape without knowing its identity,
- a route without knowing where it leads,
- a missing coworker without knowing their condition,
- a failed transmission without knowing why it failed.

The simulation must resist collapsing:

`UNKNOWN`

into:

`SECRETLY KNOWN BY THE NARRATOR`.

There is no player-facing narrator with privileged access to hidden truth.

Uncertainty is therefore not a writing inconvenience.

It is part of canonical observer state.

---

## Credibility Before Spectacle

The world should remain believable even when nothing frightening occurs.

Institutional procedures should remain coherent even when nothing goes wrong.

Personnel should remain recognizably human even when they do not produce dramatic dialogue.

Equipment should remain mundane enough that failure matters.

Environmental conditions should remain ordinary enough that discontinuity matters.

Rare phenomena should remain rare enough that encountering one alters the player's understanding of what the simulation permits.

The extraordinary gains power from the credibility of the ordinary.

---

## The Purpose of This Doctrine

This Doctrine exists to prevent reality from drifting toward whatever an implementation, provider, contributor, or current model finds convenient.

It exists so that:

- different AI providers inhabit the same world,
- future contributors preserve the same observer boundaries,
- worldpacks share simulation law without sharing terminology,
- player-facing prose remains subordinate to canonical truth,
- persistence survives technological changes,
- institutional ignorance remains possible,
- meaningful uncertainty remains possible,
- characters remain products of history rather than exposition,
- extraordinary events remain consequences of simulation rather than pacing.

Custodian is not responsible for guaranteeing a compelling scene.

Custodian is responsible for preserving a reality from which compelling scenes may legitimately emerge.

# CHAPTER I — REALITY AND ONTOLOGY

## 1.1 The Fundamental Distinction

Every interpretation inside Custodian begins by distinguishing:

**REALITY**

from

**KNOWLEDGE OF REALITY**

These are separate authorities.

Reality consists of canonical facts.

Knowledge consists of observer-held representations of some subset of those facts.

A canonical fact may exist without being known.

A belief may exist without being canonically true.

A record may describe something incorrectly.

An observer may infer correctly without possessing confirmation.

A simulation that cannot express these distinctions cannot preserve observer integrity.

---

## 1.2 Canonical Reality

Canonical reality is the authoritative world state maintained by Custodian.

It may include:

- world identity,
- time,
- geography,
- connectivity,
- environmental conditions,
- personnel identity,
- personnel position,
- personnel status,
- equipment identity,
- equipment location,
- custody,
- assignments,
- task state,
- communications,
- communication delivery,
- evidence,
- phenomenon identity,
- phenomenon state,
- entity identity,
- entity behavior state,
- injuries,
- death,
- institutional state,
- historical events.

Canonical reality answers:

> What is actually true in this world?

This authority must remain deterministic where the architecture requires determinism and persistent wherever history requires persistence.

---

## 1.3 Canonical State Is Not Player State

A common simulation failure occurs when player-visible state becomes synonymous with canonical state.

This is forbidden.

For example:

Canonical reality:

`Corridor C exists beyond Junction B.`

Player state:

`Player has not observed Corridor C.`

Standard state:

`No verified record of Corridor C exists.`

Historical record:

`Prior survey indicates a service continuation may exist west of Junction B.`

All four may coexist.

No layer should overwrite another simply because one contains more information.

---

## 1.4 Objective Events

An event is canonical when an authoritative simulation system resolves that it occurred.

Examples:

- a person moved,
- a light failed,
- equipment transferred custody,
- a transmission failed,
- an entity changed location,
- someone was injured,
- evidence was created,
- a route became inaccessible.

Text stating that an event occurred does not create the event.

An AI provider describing an event does not create the event.

A user intending an event does not create the event.

A player action is a request or attempt until authoritative resolution determines its canonical consequence.

---

## 1.5 Presentation Is Not Reality

Visuals, sounds, prose, UI state, animation, and generated media are representations.

They are not canonical authorities unless an explicit simulation system treats a corresponding event as canonical.

Examples:

A generated photograph depicting an object does not create that object.

A frightening sound effect does not establish an entity nearby.

A textual phrase saying a corridor is blocked does not block the corridor unless spatial/environment authority already says it is blocked.

A UI warning cannot reveal danger merely because hidden canonical state contains danger.

Presentation must consume authorized truth.

It must never create hidden truth by implication.

---

## 1.6 Internal Ontology

Custodian may possess exact internal classifications unavailable to any observer.

This is intentional.

Examples within Yellow Beast may include canonical internal phenomenon/entity identities such as:

`STILL_LIFE`

or

`BACTERIA`.

Internal identity exists because behavior authority requires exact knowledge of what is being simulated.

The simulation cannot afford to become confused merely because ASYNC personnel lack a name.

Internal ontology therefore controls:

- behavior,
- persistence,
- valid interactions,
- movement rules,
- environmental interactions,
- perception eligibility,
- causal consequences.

It does **not** automatically control player-facing language.

---

## 1.7 Canonical Identity and Designation Are Separate

For any phenomenon or poorly understood object, distinguish:

`CANONICAL INTERNAL IDENTITY`

from

`OBSERVER CLASSIFICATION`

from

`INSTITUTIONAL DESIGNATION`

from

`ENCOUNTER ALIAS`.

Example:

Canonical type:

`STILL_LIFE`

Worker observation:

`human-shaped form`

Initial Standard record:

`UNIDENTIFIED FORM`

Team nickname:

`Marvin's friend`

Later institutional designation:

whatever classification legitimately develops from world history.

These names may coexist.

Changing the nickname does not change canonical identity.

Learning a nickname does not teach an observer the canonical developer taxonomy.

A fresh world does not inherit an alias created in another world.

---

## 1.8 Aliases Are Historical Facts

An encounter alias is not merely flavor text.

If personnel coin a nickname and that nickname persists, its existence becomes a historical fact with provenance.

Where relevant, the simulation should be able to answer:

- who used it,
- when it appeared,
- who heard it,
- whether it entered a report,
- whether Standard adopted it,
- whether another worker knows it.

An alias may spread through legitimate communication.

It may not teleport between observers.

---

## 1.9 Worldpacks Do Not Own Fundamental Reality Law

A worldpack defines the content and interpretation of a particular world.

It may define:

- institutions,
- roles,
- equipment,
- places,
- terminology,
- phenomena,
- environmental configuration,
- assignments,
- authored scenarios,
- presentation defaults.

It may not redefine foundational Custodian invariants such as:

- canonical state precedes presentation,
- observers have bounded knowledge,
- information requires legitimate transfer,
- AI does not create truth,
- persistence cannot be casually discarded,
- player-facing text cannot silently become omniscient.

A worldpack may alter what exists.

It may not abolish the distinction between existence and knowledge.

---

## 1.10 Negative Ontology

Absence is not always a canonical fact.

Distinguish:

`KNOWN ABSENT`

from

`NOT OBSERVED`

from

`UNKNOWN`

from

`NOT YET GENERATED / INSTANTIATED`, where the simulation architecture legitimately supports unresolved generation.

Example:

A worker looks into an illuminated empty room.

They may legitimately know:

`no visible person is present within observed area`.

They may not necessarily know:

`nothing exists anywhere in this location`.

Likewise:

A missing worker is not canonically dead merely because no contact exists.

An unanswered transmission does not prove receiver destruction.

No evidence of an entity does not prove no entity exists.

Generated text must preserve these distinctions.

---

## 1.11 Contradiction Does Not Require Immediate Resolution

Custodian must support conflicting records without forcing one player-facing answer.

For example:

Historical survey:

`west route continues`.

Current observation:

`wall where route should be`.

Canonical reality may contain a phenomenon explaining this.

Or it may not yet be understood by any observer.

The system may retain:

- the old survey,
- the current observation,
- the contradiction,
- institutional uncertainty.

It need not generate an immediate explanation.

Contradiction is sometimes the correct state.

---

## 1.12 Reality Does Not Need To Be Legible

Not every canonical condition must be immediately understandable.

A system may know:

- an entity moved,
- a route changed,
- an object was displaced.

Observers may only know:

- something is different.

This gap is legitimate.

Player-facing systems must not convert hidden causality into convenient explanation.

The objective of presentation is not to explain the entire simulation.

The objective is to faithfully represent what the observer can perceive or access.

---

## 1.13 Reality Is Not Genre-Aware

Canonical systems do not know they are participating in horror.

They do not know the player expects tension.

They do not know an event would be cinematic.

They do not know an entity is iconic.

They do not know a quiet operation may seem boring.

Genre expectations may influence authored worldpack content and presentation restraint.

They may not override causal simulation.

The world does not perform for the player.

---

## 1.14 Reality Is Not Prompt-Aware

No canonical actor may reference:

- prompts,
- models,
- context windows,
- random seeds,
- save files,
- state machines,
- UI implementation,
- hidden enum values,
- developer terminology,

unless that concept legitimately exists inside the world.

An AI provider receives technical context only as scaffolding.

It must not reproduce that scaffolding as in-world knowledge.

---

## 1.15 Canonical Mutation

Canonical state may change only through authorized simulation mechanisms.

Examples include:

- validated player action,
- validated personnel action,
- environmental process,
- communication delivery,
- assignment resolution,
- equipment interaction,
- hazard resolution,
- phenomenon behavior,
- bounded institutional processing,
- explicit world lifecycle transition.

A renderer may request mutation through a legal authority.

It may not mutate canonical state directly because a button was pressed.

An AI provider may propose interpreted intent.

It may not directly write canonical state.

---

## 1.16 Canonical Persistence

Once a canonical event becomes part of world history, later systems must treat that fact as historical input.

This does not mean every field remains unchanged forever.

It means changes require causes.

Example:

`LIGHT = DARK`

may later become:

`LIGHT = NORMAL`

because power was restored.

The historical fact that the room was previously dark remains true.

Persistence means causality connects states across time.

It does not mean the world is frozen.

---

## 1.17 World Identity

Each world is its own canonical history.

World-specific state must not leak into another world without an explicitly sanctioned meta-level mechanism.

This includes:

- personnel memories,
- aliases,
- institutional discoveries,
- maps,
- evidence,
- phenomenon knowledge,
- deaths,
- assignment history,
- relationships.

A fresh world begins with only the starting knowledge defined for that worldpack and world creation process.

The player may remember another world.

The simulated institution does not.

---

## 1.18 Meta-Level Information

Custodian may maintain explicitly sanctioned meta-level records outside an individual world.

Examples may include a Legacy Personnel Archive.

Meta-level state must remain clearly separated from in-world state.

A meta archive may tell the human player:

`a previous career existed`.

It may not cause a worker in a fresh world to remember that career unless an explicit cross-world mechanic authorizes it.

Meta continuity belongs to the product.

World continuity belongs to the simulation.

Do not confuse them.

---

## 1.19 Constitutional Ontology Test

Before allowing any piece of player-facing output, ask:

1. What canonical fact supports this?
2. Which authority owns that fact?
3. Does the current observer legitimately know it?
4. Through what causal pathway did they learn it?
5. Is the wording expressing knowledge, inference, belief, or objective fact correctly?
6. Does the terminology belong to this observer?
7. Does the output accidentally reveal internal ontology?
8. Would the statement remain valid if the AI provider were replaced with deterministic text?

If any answer is unclear, the output requires additional constraint or must remain uncertain.

---

## 1.20 Chapter I Principle

The first law of Custodian is:

> **Reality and knowledge of reality are different things.**



Everything that follows in this Doctrine exists to preserve that distinction.
